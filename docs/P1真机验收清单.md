# P1 真机验收清单（手机到手后按顺序做）

> 对应计划书 3.2 节探针门禁。全程一次只开一组服务。判定报告写 `_reports/p1_verdict.md`。
> 探针红线：只读不 performAction、不碰钱、不自动发送、dump 不出本机。

## 0. 前置与装机

- 真机：Android 11+ 任意机型（免 root）；微信已登录（建议小号），**记录微信精确版本号**（我-设置-关于微信）。
- PC 在工程根目录 `D:\Z0F\AndroidDev\WeChatJevAndroid`。

```bash
adb devices                                    # 确认设备在线
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

装好后先开 logcat 常驻窗口：

```bash
adb logcat -s JevProbe
```

## 1. 基线自证（系统设置页 × 任意一组）

证明「服务本身是好的」，排除服务没起来的干扰。

1. 打开 JevProbe App →「① 打开无障碍设置」→ 找到 **Jev 探针 B（对照组）** 并开启。
2. 回到 JevProbe App，主界面应显示「对照组(Plain): 已连接 ✓」，logcat 出现：
   `[plain] service connected`
3. 停在系统设置页（或本 App 页面也行），点「② 立即 dump」。
4. **预期**：`[plain] DUMP total=<明显>0> withText=<若干>` —— 记录数字。

## 2. 微信聊天页 × 对照组（预期失败的一组）

1. 保持只开对照组。打开微信，进入**任意一个聊天窗口**，停在能看到气泡的页面。
2. PC 侧触发 dump（不要切回 JevProbe）：

```bash
adb shell am broadcast -a com.wechatjev.android.DUMP
```

3. **预期（微信 8.0.52+ 混淆）**：`total=0` 且 `rootInActiveWindow = NULL` 或全部无文本。记录数字——这正是「微信在挡普通服务」的证据。

## 3. 微信聊天页 × 实验组（裁定组）

1. 去无障碍设置**关掉对照组，只开「Jev 探针 A（伪装组）」**。logcat 应见 `[disguised] service connected`、`[plain] service torn down`。
2. 回到微信聊天页（换个会话或上下滚动一下再停稳），触发：

```bash
adb shell am broadcast -a com.wechatjev.android.DUMP
```

3. **看 logcat 两行**：
   - `[disguised] DUMP total=N withText=M ...` → 文件名
   - `[disguised] firstTexts=[...]` → 前 10 条文本各 10 字

**判定（PASS-A）**：`total > 20` 且 firstTexts 里能看到聊天气泡的**中文消息内容** → 路线成立，进 M1。

4. 取证（可选，debug 包 run-as 通道）：

```bash
adb shell run-as com.wechatjev.android ls files/dumps/
adb exec-out run-as com.wechatjev.android cat files/dumps/<最新dump文件> > dump.json
```

## 4. 补齐四组矩阵

| | 微信聊天页 | 系统设置页 |
|---|---|---|
| 伪装组(A) | 第 3 步结果 | 开 A 组停设置页，按钮②或广播 dump |
| 对照组(B) | 第 2 步结果 | 第 1 步结果 |

理想证据形态：**A 组两格都有节点、B 组微信格空根、B 组设置格有节点**——证明「伪装」是有效变量。

## 5. 截屏能力验证（决定 M5 OCR 兜底可行性）

微信聊天页停留（伪装组开启状态），触发：

```bash
adb shell am broadcast -a com.wechatjev.android.SHOT
```

- 成功：`[disguised] SHOT saved shot_disguised_*.png 1080x2400 pixels[c=... tl=... ...]`——把 pixels 五个采样值抄进报告（全 0xff000000 即全黑）。
- 失败：`SHOT FAILED errorCode=N (人话)`。若 errorCode=2（无障碍能力不允许）：把无障碍**关掉再开一次**重试；仍失败则记录——伪装服务在该 ROM 截屏被拒，M5 需按计划书评估「另起不伪装截屏服务」。
- 连发两次验证限频：第二次应打 `SHOT throttled`。
- 肉眼复核 PNG：

```bash
adb exec-out run-as com.wechatjev.android cat files/dumps/shot_disguised_*.png > shot.png
```

## 6. 稳定性观察（可与上面合并做）

伪装组开启状态下正常使用微信 10–15 分钟（收发消息、逛朋友圈、返回桌面再进）：微信零崩溃、logcat 无异常刷屏、JevProbe 进程无崩溃重启。

## 注意事项

- **一次只开一组**；两组同时开会让一次广播出两份 dump（文件按组命名可区分，但矩阵更乱）。
- MIUI/HyperOS 开无障碍路径：设置 → 更多设置（或系统与设备）→ 无障碍 → 已下载的应用；可能要求插着 SIM/连网验证，属正常。
- dump 遍历在主线程，微信大页面 dump 瞬间轻微卡顿属预期；若 logcat 显示 walk failed 或明显卡死（>2s），记入报告（M1 优化项）。
- 广播触发时 JevProbe 若被 ROM 杀后台（切出后），服务可能已断——回到矩阵步骤前先确认 logcat 有 service connected。
